# 制約事項

- Windows 11の位置情報サービスとデスクトップアプリ位置情報アクセスが無効だと、Native Wi-Fi APIはBSS一覧をエラー5で拒否する。管理者昇格だけでは代替できない。
- BSS Load IEをドライバーが公開しないAPでは実利用率を取得できない。本ツールは中立点と欠損表示を使い、混雑度を捏造しない。
- HT/VHTはIEの存在だけを検出し、MCS、チャネル幅、空間ストリーム等はデコードしない。HE/EHT CapabilitiesはExtension Element（ID 255）の拡張ID、世代別可変長構造、仕様改訂の扱いが複雑で、誤った実測値を表示するリスクを避けるため未対応である。
- BSS Transition ManagementはExtended Capabilitiesが3オクテット以上ある場合だけbit 19を解釈する。IE未提供・短縮時は「非対応」ではなく取得不可とする。
- `WLAN_AVAILABLE_NETWORK`の既定認証/暗号アルゴリズムはSSID単位の情報であり、`WLAN_BSS_ENTRY`にはBSSID単位の対応フィールドがない。本版のAP詳細では認証方式・セキュリティ方式をBSSID実測値として推測せず「取得不可（Windows APIはSSID単位でのみ提供）」と表示する。RSN/WPA IEの独自デコードは未実装である。
- 最終検出日時はAPが広告するビーコンTimestampではなく、本ツールがスキャン結果としてBSSIDを観測し`last_seen.tsv`へ保存したローカル時刻である。同時実行プロセス間の厳密なファイルロックや古いBSSID記録の自動削除は未実装である。
- リンク速度は現在接続中のWLANインターフェイスについて`GetIfEntry2`が返す公称送受信速度であり、実効スループットではない。未接続BSSIDの速度は取得できない。
- Station Countは関連付け端末数で、通信量・バックホール混雑・認証サーバー状態を表さない。
- `pDesiredBssidList`は希望であり、Windows、ドライバー、802.11k/v/rローミング判断により別BSSIDになる場合がある。実BSSID一致時だけ指定成功とする。
- Intel BE201固有の320 MHz幅、MLOリンク単位情報、PHY速度は本版のスコアに含めない。中心周波数から主チャネル相当だけを表示する。
- 保存済みプロファイルだけを使用する。プロファイル未作成、プロファイル名/SSID XMLの特殊なエスケープ表記、ユーザー資格情報入力が必要な場合は接続できない。
- `Microsoft-Windows-WLAN-AutoConfig/Operational`は診断レポート生成時に読み取り専用で照会する。チャネルが無効/不在、イベントが保持期間外、読み取り権限不足、OSイベントXMLのフィールド差がある場合は一部または全部を取得できない。取得不能はレポート内に明記し、履歴やBlack Boxを失敗させない。
- 自動最適化は`GetAdaptersAddresses`で有効な非APIPA IPv4アドレスの有無まで確認する。これはDHCP成功の直接判定ではなく、DNS、既定ゲートウェイ、学内サービス、インターネット到達性を保証しない。大学ネットワークへ余分な負荷を与えないため、ping、HTTP、DNS等の外部疎通プローブは意図的に行わない。
- IPv4確認は500 ms間隔、最大約8秒の固定上限である。DHCP等が8秒を超えた場合は失敗として1回だけロールバックするため、低速なネットワークでは偽陰性になり得る。タイムアウトの設定化とIP構成変更通知による待機は未実装である。
- 遅延/疎通計測は未実装。切替前後比較はRSSIとWindows Signal Qualityの観測値であり、スループットやアプリケーション品質の改善を証明しない。
- 自動監視はログオン中の独立プロセスでありWindowsサービスではない。再起動後の自動開始機能は未実装で、タスクスケジューラを勝手に変更しない。
- クールダウン時刻はプロセス内だけに保持するため、監視プロセスを再起動するとリセットされる。
- OFF要求は待機中なら最大約500 msで反映するが、進行中の`WlanConnect`自体は安全にキャンセルせず、最大タイムアウト後に停止する。
- 履歴はローカルTSVで、資格情報は含まない。ファイルサイズの自動ローテーションは未実装。
- Black Boxは直近500障害レコードでローテーションするが、障害前スナップショットのリングはプロセス内だけであり、プロセス開始前や観測間の状態は復元しない。`blackbox.jsonl`の同時read-modify-writeに対するプロセス間ロックは未実装である。パスワード、秘密鍵、証明書本体、ユーザー資格情報は取得・記録しない。
- 複数WLANインターフェイスがある場合、接続中のものを優先し、なければ最初のインターフェイスを接続に使用する。
- 接続履歴には接続試行の開始・終了時刻または`duration_ms`がないため、`history --stats`は平均接続時間を算出せず「未計測」/`null`とする。過去データから推測はしない。
- one-shotの`optimize --dry-run --explain`はdaemonプロセス内だけにある最終切替時刻を参照できないため、クールダウンを非アクティブとして表示する。候補、改善幅、ヒステリシス判定は通常の`optimize_once`と同じ経路である。
- `simulate`はschema version 1の`scan --format json`を対象とする。外部JSONのUnicode `\u` サロゲートペアや将来スキーマは対応外で、不正入力として拒否する場合がある。
- `watch`は各周期の結果を保持せずメモリ増加を避ける設計だが、1時間以上の長時間安定性および動的リーク検査は時間的制約により未実施である。
- GUIの通知領域アイコンにはWindows Shell（通常は`explorer.exe`）が必要である。Explorer再起動後は`TaskbarCreated`でアイコンを再登録するが、Shellが利用できず初回登録に失敗した場合、閉じるボタンはアクセス不能を避けるためタスクバーへの最小化にフォールバックする。
- GUIはPer-Monitor DPI Awareness v2を要求し、DPI変更時にウィンドウとフォントを再配置する。ただし、複数DPIモニター間の移動を含む外観の目視検証は未実施で、固定ピクセル相当の最小サイズや列幅に改善余地がある。
- GUIはスキャン/接続をワーカースレッドへ移すが、一度に実行できるWLAN操作は1件である。終了時は安全なリソース解放のため進行中操作を待つので、接続通知のタイムアウト中は終了完了まで最大約25秒かかり得る。
- GUIのSSIDドロップダウン候補は、起動時または「Refresh」時のスキャンで見えている周辺ネットワークだけである。非表示SSIDや一時的に圏外のSSIDは候補に出ないが、編集欄へ直接入力できる。
- 対象SSIDの変更はランキングと自動最適化の対象設定を切り替えるだけであり、Windows Wi-Fiプロファイルを作成しない。対象SSIDへ接続するには、そのSSID用の保存済みWindowsプロファイルが別途必要である。
- Native Wi-Fiの接続通知はGUIメッセージループへ直接統合せず、既存`WlanClient`の条件変数待ちをワーカースレッドで使用する。OSからの継続的なWLAN状態変化はプッシュ表示されず、「Refresh」または操作完了時に再取得する。
- 自動最適化ONはGUIと同じディレクトリの`wifiopt.exe`を必要とする。GUI実行ファイルだけを別の場所へ移動すると監視プロセスを開始できず、設定は安全のためOFFへ戻る。
- Closed-loop Optimizationの実AP切替、実BSSID一致、実IPv4取得、IP失敗時ロールバックは、安全上の制約により今回の開発環境では未検証である。合成データの単体テスト、ビルド、dry-run、コードレビューの結果を実機成功として扱わない。
